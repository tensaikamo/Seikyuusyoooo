# 日給管理・請求書

日給制の勤怠入力、月次集計、請求書の作成、発行履歴の管理を iPhone で行う依存ゼロの PWA です。

現在のアプリバージョン: **1.7.0**

## 主な機能

- 従業員ごとの日勤・夜勤・残業・車代の入力
- 暦月の集計と締め日ベースの請求期間集計
- 個別請求書 / まとめ請求書のプレビュー
- A4 印刷、およびブラウザの印刷画面からの PDF 保存
- 発行時点の請求内容をスナップショットとして保存
- 発行済み請求書の再表示・再印刷
- 元の発行記録を消さない取消記録
- JSON バックアップの保存・復元
- PWA / オフライン利用

## 金額計算

### 1日の自動計算

- 日勤: `日給 × 出勤数`
- 日勤残業: `日給 ÷ 8 × 1.25 × 残業時間`
- 夜勤: `夜間単価 × 夜勤出勤数`
- 夜勤残業: `夜間単価 ÷ 8 × 1.25 × 夜間残業時間`
- 車代: その日の設定額

残業代は、対応する日勤または夜勤の出勤数が 0 の日は計上しません。
手入力の合計額が設定されている日は、自動計算額より手入力額を優先します。

### 消費税

請求書の税抜小計に税率を掛け、請求書単位で端数を切り捨てます。
現在の設定画面では 10%、8%、0% を選択できます。

### 締め期間

- 1〜28日締め: 前回締め日の翌日から当月締め日まで
- 29〜31日設定: 月末締めとして暦月1日から月末まで

月境界・年境界・2月を含め、前後の請求期間が重複しないことを回帰テストで確認します。

## データ保存

通常データはブラウザの **IndexedDB** に保存します。

保存対象:

- 従業員
- 勤怠レコード
- 設定
- 発行履歴
- 初期設定完了状態

IndexedDB のデータ構造は 1.7.0 への更新でも変更していません。既存端末の保存データをリリース時に一括変換する処理はありません。

## バックアップと復元

バックアップは JSON 形式で保存します。新しいバックアップには `schemaVersion: 1` を付けます。

復元時は、データを上書きする前に次を検査します。

- 従業員・勤怠・発行履歴の ID 形式と重複
- 勤怠が存在する従業員を参照していること
- 同一従業員・同一日の勤怠重複
- 日付形式と実在日
- 金額・時間・出勤数の範囲
- 設定値の形式
- 発行履歴の基本構造
- 現在未対応の将来 schemaVersion

全件検査に成功した場合だけ、複数データを **1つの IndexedDB transaction** で保存します。途中で失敗した場合に、一部だけ新しいデータへ切り替わることを避ける設計です。

`schemaVersion` が存在しない従来バックアップも、現在の検証条件を満たす場合は復元対象にします。

## 発行履歴と取消

新規発行では、発行履歴の IndexedDB 保存が完了したあとに印刷画面へ進みます。保存に失敗した場合は印刷を開始しません。

新規の取消は元の発行レコードを書き換えず、次の情報を持つ取消レコードを追加します。

- 取消日時
- 取消理由
- 処理担当者
- 元の発行記録 ID
- 元請求を打ち消す金額

旧バージョンで `voided=true` が付いている発行履歴も表示互換を維持します。

## 請求番号

1.7.0 以降の新規発行では、発行履歴を基準に `YYYY-NNNNNN` 形式の年次連番を使用します。

例: `2026-000001`

従来形式の請求番号は書き換えません。過去の発行履歴はそのまま再表示します。

## 電子取引データの保存について

このアプリにはバックアップ復元と全データ削除の機能があります。そのため、アプリ単体を「訂正・削除が物理的にできない保存システム」として扱う設計にはしていません。

設定画面から出力できる事務処理規程は、発行・取消の記録を運用するための補助です。実際に必要となる保存期間、検索性、訂正・削除時の管理記録などは、利用者側の運用と適用法令に合わせて管理してください。この README やアプリ表示は、法令適合を単独で保証するものではありません。

## 全データ削除

設定画面の「全データ削除」は IndexedDB のアプリデータを削除する破壊的操作です。実行前にバックアップを保存してください。

## PWA 更新

Service Worker はアプリ本体をネットワーク優先で取得し、オフライン時にキャッシュへ退避します。

「最新に更新」は、このアプリが使用する `invoice-*` キャッシュと現在の Service Worker registration のみを対象にします。同一 origin 上の他アプリの CacheStorage / Service Worker を一括削除しません。

## テスト

Node.js 20 で実行できます。外部 npm 依存はありません。

```bash
node --test tests/*.test.js
```

テストはコピーした別実装ではなく、実際の `app.js` の副作用が始まる前の計算・検証関数を VM で読み込んで確認します。

主な回帰対象:

- 日勤 / 夜勤 / 残業 / 車代 / 手入力合計
- 数値上限と異常値
- 消費税計算
- 締め期間と2月・年境界
- 同一日の二重請求防止
- 請求番号の連番
- 発行履歴保存後の印刷
- バックアップ検証と復元順序
- 取消記録の追記方式
- PWA 更新範囲
- 印刷請求書の角印
- 車代初期値の適用条件
- 表示バージョン / PWA キャッシュ世代

`.github/workflows/core-tests.yml` でも pull request ごとに同じテストを実行します。

## ファイル構成

- `index.html` — UI / スタイル

- `manifest.json` — PWA manifest
- `sw.js` — Service Worker
- `tests/core-invariants.test.js` — 回帰・不変条件テスト
- `.github/workflows/core-tests.yml` — CI
